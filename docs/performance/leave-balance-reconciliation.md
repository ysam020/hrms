**Interpretation [Suspected]:**

- **A** was converted into the object shape on 11 July by `ensureTrackedBalance` (leave-service), the first time the employee applied for leave (4 pending PL applications exist). It hasn't been accrued since.
- **B** has received monthly accruals.
- So the balance the employee and payslips _see_ (A) is frozen, while the one the scheduler maintains (B) is invisible.

## 2. Is the balance authoritative or derived?

**Authoritative mutable state [Code].** `LeaveBalance` is updated incrementally by:

- the monthly accrual (`scheduler-service/jobs/updateLeaveBalance.ts`: carry-forward plus monthly policy accrual);
- leave approval and cancellation (`leave-service/handlers/leaveBalanceHelpers.ts`: `adjustBalance`, `accrueMonthlyLeave`, `ensureTrackedBalance`);
- attendance conflicts (`attendance-service/utils/leaveConflict.ts`: `creditBalanceBack`);
- `reconcileAttendance`.

There is **no transaction ledger**, so a balance can't be replayed exactly from events. It _can_ be re-derived approximately from:

- (a) the tenant leave policy (annual quota, monthly accrual, carry-forward rules from `tenant_settings`);
- (b) the employee's joining date;
- (c) genuine approved leave applications.

For this employee:

- **genuine** leave history = 4 PL applications, all _Pending_ (none approved), and no comp-off credits;
- the 9 _Approved_ leaves (2 CL, 5 PL, 2 SL) were **generated by the seed** [Measured].

## 3. A second, independent defect: two incompatible balance shapes **[Code + Measured]**

- The seed, `reconcileAttendance` and `updateLeaveBalance` (carry-forward) use **`balances: [{month, year, earnedPL, usedPL, usedLWP, remainingPL}]`**.
- `leave-service` (`getTrackedRemaining`, `adjustBalance`, `ensureTrackedBalance`) and `attendance-service` (`creditBalanceBack`) treat `balances` as **`{ PL: number, SL: number, … }`**. `ensureTrackedBalance` spreads whatever is there (`{ ...row.balances, [type]: amount }`), which turns an array into `{ "0": …, "1": …, "2": …, PL: … }`.

Measured shapes in `hrms-acme-corp`:

| Shape                                 |                                             Rows |
| ------------------------------------- | -----------------------------------------------: |
| Array                                 |                                              105 |
| **Hybrid** (array spread into object) | **2** (copy A + one row not created by the seed) |
| Pure object                           |                                                1 |

`reconcileAttendance` then crashes on hybrid rows (`balances.find is not a function`, seen in the local scheduler log on 2026-10-31). **Any** of the 105 array-shaped employees who applies for a leave type the code doesn't find will have their row converted. This is a correctness bug in its own right (backlog D16) and must be fixed before or with the reconciliation, or the problem recurs.

## 4. Recommended resolution (for approval)

Don't pick a copy by timestamp or by balance. Both started from seed data with random values.

1. **Fix the shape defect first** (development change, separate review). One canonical shape, with read and write helpers that accept both shapes and migrate on write.
2. **Rebuild this employee's balance** on staging from the tenant policy, joining date and genuine leave history, excluding the 9 seed-generated approved leaves. The result goes into **one** row in the canonical shape.
3. **HR sign-off** on the rebuilt figure. The employee has 4 pending PL applications whose approval depends on it.
4. **Production apply (separate approval):**
   - archive both rows (encrypted, restricted);
   - update copy A (the one readers already resolve to, so no visible flip) to the signed-off canonical value;
   - delete copy B;
   - then the `leavebalances_tenantId_userId_key` unique index can be built.

## 5. Validation

- Staging: `getLeaveBalance` for the employee returns the signed-off figure; the 4 pending applications still validate.
- After apply: exactly one row per `(tenantId, userId)` (count query); the shape is canonical; the next accrual run updates that row (check `updatedAt`).
- Payslip and attendance-summary readers (`findFirst`) return the same row.

## 6. Rollback

Restore both rows from the archive by `_id` and drop the unique index if it was built (index drop is non-destructive). Since only copy A's content changes and B is archived, rollback is a single restore.
