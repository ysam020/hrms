# React 19.x Feature Adoption — apps/web

**Rule applied:** adopt only stable features that improve correctness, maintainability or performance **without changing the visible UI or interaction patterns**. Release attribution and stability were verified against the React changelog, the react.dev 19.2 and 19.3 posts, and the exports of the published 19.3.0 tarball (see the experiment's `REACT_19_FEATURES.md`). The behaviour-sensitive features below are deferred, not rejected: each would change how screens animate or submit, so each needs its own design review.

## Adopted

| Feature                                                                        | Release                   | Where                                       | Benefit                                                                                                                                                                                                            | UI change?                       | Verified by                                                       |
| ------------------------------------------------------------------------------ | ------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- | ----------------------------------------------------------------- |

In production the message is redacted (tokens, JWTs, emails, PAN/Aadhaar-shaped numbers, query strings); development keeps the full error. A single hook point for a future monitoring sink. | No                               | Unit tests (redaction, one report per error)                      |
| `useEffectEvent`                                                               | 19.2                      | `src/app/session.tsx` (402 handler)         | The transport's handler is registered once yet reads the current user; replaces a ref written during render                                                                                                        | No                               | Lint (plugin 6.1.1 understands Effect Events); 402 flow identical |
| `inert` as a boolean DOM property                                              | 19.0 (behaviour change)   | `motion/Presence.tsx`, `shell/AppShell.tsx` | Leaving overlays and the hidden sidebar are inert again; React 19 drops the old `inert=""`                                                                                                                         | No (restores React 18 behaviour) | Presence test; regression test; DOM facts in the browser          |
| `RefObject<T \| null>` typing; `useRef` requires an argument                   | 19.0 types                | landing hooks, 4 timer refs                 | Types match React 19's ref semantics                                                                                                                                                                               | No                               | Typecheck                                                         |
| eslint-plugin-react-hooks 6.1 rules                                            | 19.2 era                  | `eslint.config.js` (apps/web)               | Rules of Hooks and effect dependencies enforced; 3 suppressions removed, 7 dependency findings fixed (2 kept with documented reasons)                                                                              | No                               | `pnpm lint`                                                       |

## Deferred, with the reason

| Feature                                                     | Release     | Candidate in Praesto                             | Why not now                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------- | ----------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Actions, `useActionState`, `useFormStatus`, `<form action>` | 19.0        | Leave apply, support ticket, KYC, settings forms | The forms work and use offline drafts and the mutation queue (`sendOrQueue`). Moving them to Actions changes submit and pending timing and React's automatic form reset. Do it form by form with visual checks. Recommended first: support ticket.                                                 |
| `useOptimistic`                                             | 19.0        | Notification clear, chat send                    | `shell/Notifications.tsx` already clears optimistically with manual rollback on failure; `useOptimistic` would restate it with no user-visible change. Approvals stay server-authoritative by design. Chat is a candidate after a real-socket test.                                                |
| `use(promise)` / `use(context)`                             | 19.0        | Route data, contexts                             | Data loading is built on `useGet` / `useFetchData` / `useServerPagination` with abort and caching. Replacing those is a data-layer redesign, not a version upgrade.                                                                                                                                |
| `ref` as a prop (remove 15 `forwardRef`)                    | 19.0        | `ui/fields.tsx`, motion links, overlays          | `forwardRef` still works in 19. Removing it is churn with no user benefit; do it alongside other edits to those files.                                                                                                                                                                             |
| `<Context value>` as provider                               | 19.0        | 38 `.Provider` usages                            | Cosmetic.                                                                                                                                                                                                                                                                                          |
| Document metadata (`<title>`, `<meta>` in components)       | 19.0        | `app/seo.ts` `applyPageMeta`                     | The prerender pipeline writes `<head>` at build time. Two metadata systems would compete. Revisit only if the prerender script changes.                                                                                                                                                            |
| `preload` / `preinit` / `preconnect` APIs                   | 19.0        | Fonts, API origin                                | System fonts; the API is same-origin; Vite already emits `modulepreload`.                                                                                                                                                                                                                          |
| Owner Stacks                                                | 19.1        | Dev error context                                | Already active in development builds; nothing to adopt.                                                                                                                                                                                                                                            |
| `<Activity>`                                                | 19.2        | Keep a list alive behind a detail screen         | Changes what re-fetches on back-navigation (state is kept and effects pause). That's a UX change; propose it separately with product.                                                                                                                                                              |
| Performance Tracks                                          | 19.2        | Profiling                                        | Available now in dev builds; workflow documented in PERFORMANCE_COMPARISON.md. Nothing to change in code.                                                                                                                                                                                          |
| `cache` / `cacheSignal`, partial pre-rendering / resume     | 19.0 / 19.2 | —                                                | Server Components / streaming SSR only. Praesto prerenders with `renderToString` and has no RSC.                                                                                                                                                                                                   |
| `<ViewTransition>` + `addTransitionType`                    | 19.3        | Page transitions                                 | The app's transitions come from React Router 6's `viewTransition` plus framer-motion. React's `<ViewTransition>` needs navigations to run as React transitions (React Router 7 `useTransitions`) and would change animation behaviour. That requires the router major upgrade and design sign-off. |
| Fragment refs                                               | 19.3        | Focus into overlay content                       | `ui/layers.tsx` already manages focus correctly (unchanged focus in all dialog tests).                                                                                                                                                                                                             |
| `browser()`                                                 | 19.3        | —                                                | Suspends during server rendering. The prerendered pages don't need it (the landing already guards browser-only code).                                                                                                                                                                              |
| Trusted Types support                                       | 19.3        | `ui/RichText` (DOMPurify)                        | Becomes relevant only if a `require-trusted-types-for` CSP is introduced; then make DOMPurify return Trusted HTML.                                                                                                                                                                                 |
| React Router 7                                              | —           | Router                                           | Not required for React 19 (v6.30 supports it). A separate, larger migration: route modules, `useTransitions`, and its interaction with the existing view-transition layer.                                                                                                                         |

**No experimental or canary API is used.**
